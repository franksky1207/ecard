# 智慧刷卡提醒｜完整架構、功能、建立歷程與後續改進

> 建檔：2026-10-16（臺灣時間）  
> 專案：`franksky1207/ecard`；網頁：https://franksky1207.github.io/ecard/  
> 用途：供未來維護、換對話、功能改進時作為交接文件。**網頁原始碼與實機驗證結果要分開判讀；本文件不代表所有背景通知已驗收。**

## 1. 目標與架構

目標：依每週課表或特殊日期的上下班時間，查詢學校實際刷卡紀錄，僅在未完成有效刷卡且達提醒時機時通知。支援開關、延遲、特殊日、備份，避免修改程式才能改時間。

**設定資料流**：GitHub Pages 網頁設定中心 → Safari localStorage 儲存 →「複製到 iPhone」將 JSON 放入剪貼簿 → 使用者在 Scriptable `school` 手動匯入。**不是即時同步**。

**執行資料流**：iPhone 捷徑「刷卡自動檢查」定時觸發 → Scriptable `Run school` → 使用保存在 Scriptable Keychain 的登入資料查詢學校系統 → 比對有效刷卡紀錄、日期與提醒設定 → 需要時由 iPhone 發出通知。

**角色分工**：
- 網頁：設定編輯、特殊日、開關、瀏覽器本機儲存、剪貼簿複製、JSON 備份。
- Scriptable：學校登入、出勤查詢、有效刷卡判斷、提醒條件與通知；帳密不放在 GitHub。
- iPhone 捷徑：負責在指定時間啟動 `school`，不負責解析學校刷卡紀錄。
- 學校刷卡系統：實際出勤紀錄來源。

## 2. 網頁現有功能（以 `main/index.html` 為準）

### 提醒控制
- 智慧提醒總開關 `enabled`
- 上班提醒 `morningEnabled`
- 下班提醒 `eveningEnabled`
- 再次確認 `recheckEnabled` 與間隔分鐘 `recheckDelay`（預設 10）
- 以上開關及時間可由使用者自行調整。

### 每週時間表
星期日到星期六各自獨立設定：
- `enabled`：當天是否需要上班
- `start`：上班有效刷卡最晚時間（預設 07:30）
- `end`：下班有效刷卡最早時間（預設 16:45）
- `workReminders`：多個上班提醒時間（預設 06:30、07:00）
- `leave`：預計下班時間
- `advance`：**下班後延遲提醒**分鐘數；欄位沿用舊鍵名以維持資料相容，並非提前提醒

網頁程式目前預設星期一／四／五預計 20:40、星期二／三 17:30、週末不上班；`advance` 的程式預設值是 **5 分鐘**。使用者已儲存／匯入的實際設定可能不同，不能將先前對話中 2 分鐘的例子視為正式現值。

### 特殊日期
- 指定日期、休假／請假或補班／加班／調整時間
- 特殊工作日可獨立設定刷卡門檻、預計下班、延遲提醒、上班提醒時間、備註
- 日期覆寫優先於每週時間表；不永久修改星期設定
- 可編輯與移除；修改後需按「儲存設定」

### 儲存／同步／備份
- **儲存設定**：寫入當前瀏覽器 `localStorage`，鍵名 `ecard-settings-v1`。
- **複製到 iPhone**：複製目前設定 JSON 到剪貼簿；必須再於 Scriptable 手動匯入。按鈕不是背景傳輸或自動同步。
- **下載備份**：下載 `ecard-settings.json`。
- **還原備份**：讀取 JSON 並驗證，還原到編輯畫面後仍須儲存。
- 設定資料內沒有學校帳號或密碼。瀏覽器清除資料可能造成設定遺失。
- 網頁為響應式手機／桌面介面，2026-10-16 已精簡過時文字、分組按鈕及優化手機排列。

### 資料相容與限制
- 網頁設定的儲存鍵仍為 `ecard-settings-v1`，資料內版本欄位 `version: 2`；避免任意改動既有欄位及 JSON 格式。
- 網頁沒有自行登入學校、背景查詢或發送系統通知；相關工作由 iPhone 端處理。
- 修改網頁設定並不會自動更新 Scriptable，更不會自動調整捷徑觸發時刻。

## 3. Scriptable：`school` 程式

已在使用者 iPhone 安裝並曾完成手動測試：
- 透過 Scriptable Keychain 保存學校登入憑證，不應提交 GitHub。
- 能登入學校系統並讀取出勤刷卡紀錄（先前實機手動測試成功）。
- 能從網頁複製的 JSON 匯入提醒設定（先前實機測試成功）。
- 設計上依提醒開關、日期、時間及刷卡紀錄決定是否通知；可設定再次確認。
- 曾針對「早上連刷兩次」修正判定：例如 06:21 同時顯示上班與下班欄位，**不應認定已完成真正下班刷卡**；下班紀錄需達當日 `end` 門檻才有效。
- 先前討論中提到 Scriptable 捷徑模式使用提醒時刻附近的約五分鐘判斷窗；正式程式碼位於手機，**本 GitHub 儲存庫的網頁原始碼不能直接證實手機端當前完整程式**。修改 Scriptable 前應先備份並核對手機實際 `school` 版本。

**待驗證**：手機鎖定時，`Run school` 是否能完整登入、查詢、判斷並發送正式刷卡提醒；再次確認與特殊日期端到端行為亦尚未完整驗收。

## 4. iPhone 捷徑／自動化

- 捷徑名稱：「刷卡自動檢查」
- 核心動作：Scriptable → `Run school with Parameter`
- 已使用時間觸發條件及「自動化操作」開啟、「執行前確認」關閉；捷徑本身的執行提示「通知」可關閉，與 `school` 發出的刷卡通知不同。
- 先前規劃的固定觸發時間：06:30、07:00、17:32、20:42；**這些是當時的排程規劃，不保證與目前 Scriptable 匯入的延遲分鐘數一致**。例如 20:40 + 5 分鐘應為 20:45，不是 20:42。
- 曾用臨時觸發時間、在 `Run school` **前方**加入「顯示通知」測試；鎖定手機後使用者成功收到測試通知。這證實至少一次定時捷徑觸發成功，但**不能證明後面的 Scriptable 查詢成功**。
- 測試通知與臨時時間應在測試後移除；實際是否已移除，以手機捷徑畫面為準。
- 固定時間觸發無法自動配合網頁上任意特殊日期或臨時變更的提醒時間；即使 Scriptable 已匯入新設定，沒有相應觸發仍可能漏檢。

## 7. 後續優先改善順序

1. **P0 完整背景驗證**：在正式時刻或安全測試時刻確認 `Run school` 從觸發到查詢及通知均成功；不要以捷徑前置測試通知取代完整驗收。
2. **P1 時間一致性**：對照網頁已儲存、Scriptable 已匯入及捷徑觸發的實際時間，尤其 `advance` 預設 5 分鐘與先前 2 分鐘觸發例子的差異。
3. **P1 特殊日排程**：研究可行的 iOS 觸發方式，讓臨時更動時間不需逐次手動改捷徑；先評估 iOS 背景執行限制與耗電，再選方案。
4. **P2 設定同步**：減少網頁複製→Scriptable 匯入步驟；須考慮授權、安全及離線可用性。
5. **P2 執行紀錄與故障提醒**：至少顯示最近檢查時間、成功／失敗、判定結果；避免沒有通知就無法判斷是否運作。
6. **P2 去重與再次確認驗收**：防止重複通知，並驗證重新查詢機制。
7. **P3 介面與文件**：維持手機優先、用語一致、保留備份與還原，不為介面修改破壞既有設定格式。

## 8. 維護規則與安全界線

- 網頁正式來源：GitHub `franksky1207/ecard` 的最新 `main`；手機 Scriptable／捷徑的實際內容須由手機驗證，不能假定 GitHub 已含手機程式。
- **不可**將學校帳號、密碼、Cookie、登入 Token 或個人出勤紀錄提交到公開 GitHub。
- 只調整 UI 時，不變動 JSON 格式、儲存鍵、Scriptable 邏輯、提醒判定或捷徑排程。
- 改動提醒時間時，應同步檢查網頁→Scriptable→捷徑三個層級；僅按網頁「儲存設定」不足以使手機採用新設定。
- 網頁備份不含學校帳密；換機時應另外安全處理 Scriptable Keychain。
- 每次修改都要明確標示「程式已實作」「手動測試通過」「背景端到端通過」三種不同證據等級。
